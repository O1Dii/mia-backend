# Mia: хвосты и планы «на когда-нибудь»

Дата: **9 октября 2026 года**.

Здесь собрано то, что сознательно не входит в MVP/PoC из
[Mia_Architecture_Review.md](Mia_Architecture_Review.md). Для каждого пункта
указано, **когда к нему возвращаться** и **с чего начать**. Это не
исполняемые session cards. Пункт попадает в план, когда срабатывает его
условие.

## 1. Регионы, право и провайдеры

**Когда возвращаться:** до публичного запуска, до приёма платежей и до
первых пользователей, которые не являются знакомыми команды.

Позиция на время PoC описана в §9 ревизии: нейтральный BYOK-клиент,
только API-ключи, без рекламы «обхода».

### 1.1. Условия провайдеров для посредника

Технически запрос уходит к провайдеру с IP сервера Mia (например, Hetzner,
Германия), а не с IP пользователя. Поэтому для провайдера это выглядит как
обращение из поддерживаемого региона.

Риск в том, что OpenAI, Anthropic и Google ограничивают использование API
из неподдерживаемых стран (Россия и Беларусь в их числе на дату
исследования). Если Mia **сознательно** предлагает такой доступ
пользователям из этих стран, это может считаться содействием обходу.
Последствия — блокировка ключей пользователей, а при масштабе — IP или
аккаунта Mia.

Исследовать:

- [ ] Актуальные тексты Usage Policies / Supported Countries / Terms
  OpenAI, Anthropic, Google, xAI, DeepInfra, OpenRouter. Что сказано о
  посредниках и о «доступе из неподдерживаемых регионов через третьи
  сервисы»?
- [ ] Допускают ли условия хранение ключа пользователя сервисом-посредником
  и запросы от его имени (BYOK)? Как это делают TypingMind, LibreChat
  Cloud, OpenRouter BYOK?
- [ ] Можно ли использовать ключ пользователя для запросов **сторонних
  приложений** через «Войти через Mia» (§8 ревизии)? Это повторное
  посредничество; нужна отдельная проверка.
- [ ] Anthropic: запрет маршрутизации через подписки Free/Pro/Max (уже
  учтён). Отслеживать изменения и возможные программы вроде «Agent SDK
  credits».
- [ ] OpenAI Sign in with ChatGPT: для разработки используется поток для
  open-source и самостоятельно размещённых приложений (ревизия §5.5). Для
  многопользовательской хостинговой Mia нужна заявка через interest form.
  Подать её, когда понадобится, чтобы пилотные пользователи входили своей
  подпиской Plus/Pro. Стоит ли открыть исходники Mia ради этого потока?

### 1.2. Санкционные и корпоративные вопросы оператора

- [ ] Где будет юрлицо Mia и где живут разработчики (BY/RU/другое)?
- [ ] Условия хостинга (Hetzner и др.) и платёжных систем (Stripe, Paddle,
  App Store, Google Play) для операторов и пользователей из BY/RU.
- [ ] Ограничения ЕС на оказание IT-услуг и ПО лицам из России и Беларуси:
  касаются ли они бесплатного BYOK-сервиса и платной подписки.
- [ ] Возможность приёма платежей от пользователей из разных регионов:
  отдельные каналы, налоги.

### 1.3. Персональные данные

- [ ] **152-ФЗ (РФ):** требование первичной записи персональных данных
  граждан РФ в базах на территории РФ. Применимо ли к Mia при целевом
  русскоязычном рынке? Что считается «направленностью на РФ»?
- [ ] **Беларусь (Закон № 99-З):** трансграничная передача, согласия,
  регистрация оператора.
- [ ] **GDPR:** если пользователи есть в ЕС. Роль Mia (controller или
  processor), DPA с провайдерами. Влияет ли E2EE (V2) на статус данных
  (CJEU C-413/23 P против позиции EDPB 01/2025).
- [ ] Варианты архитектуры при конфликте требований: отдельный регион
  хранения аккаунта и памяти, E2EE, Personal Node.

### 1.4. Альтернативные провайдеры для пользователей без доступа

- [ ] **GigaChat** (Сбер): API, условия, tool calling, адаптер (есть
  OpenAI-совместимые прокси вроде `gpt2giga`; оценить, нужен ли свой
  адаптер).
- [ ] **YandexGPT / Yandex AI Studio**: OpenAI-совместимый endpoint,
  tool calling, цены. Подключается через generic-адаптер.
- [ ] Доступность OpenRouter и DeepInfra для оплаты из BY/RU.
- [ ] Прогнать контрактные сценарии действий на лучших из них, чтобы
  перевести их в «проверенные профили».

### 1.5. Режим прямого вызова провайдера с телефона

Android вызывает провайдера напрямую с ключом из Keystore. Запрос идёт с
IP пользователя, Mia не видит ни ключ, ни промпт. Минус — второй агентный
цикл на Kotlin и фон без сервера.

- [ ] Оценить, если вопрос посредничества (1.1) окажется острым.

## 2. Personal Node

**Когда возвращаться:** после пилота, если пользователи хотят локальные
модели (Ollama на ПК), работу с файлами или строгий локальный режим
хранения.

- [ ] То же Python-ядро как процесс на ПК/сервере пользователя (SQLite
  вместо Postgres через repository interfaces).
- [ ] Pairing по QR, ключи устройства, исходящий WSS к relay (см.
  `Mia_Architecture.md` §6).
- [ ] Маршрутизация run на узел, `waiting_for_node`, явный fallback.
- [ ] Хранение памяти и истории на узле; облако знает только метаданные.
- [ ] Совместимость с OpenClaw / Hermes как узел или канал (исследовать).

## 3. Приватность: следующие уровни

**Когда возвращаться:** после MVP, когда Memory Ledger и per-user DEK
работают.

- [ ] **V2:** перевод истории и чувствительной памяти на ключ пользователя.
  Ключ получается из passkey (WebAuthn PRF) с обязательным кодом
  восстановления и одобрением с другого устройства. Ядро получает ключ на
  время активной сессии; фоновым задачам доступен только «профиль
  автоматизаций».
- [ ] **V4:** «приватная модель» на open-weights через аттестованный TEE
  (Tinfoil, NEAR AI, Phala) с проверкой аттестации.
- [ ] Reproducible builds и подписанные релизы клиентов. Иначе обещание
  «не можем прочитать» опровергается вредоносным обновлением клиента.
- [ ] Сессия Telegram на сервере (L2) только вместе с V2.

## 4. Голос

- [ ] **Wake word «Привет, Мия».** Корпус из своего голоса, 10–20 человек и
  шума; обучение openWakeWord-совместимой модели (синтетика + реальные
  записи). Замер ложных срабатываний за 8 часов, пропусков и батареи.
  Opt-in, в foreground service ассистента (исключение VIS).
  *Когда:* после измеренного каскадного голоса.
- [ ] **Realtime-режим голоса (Gemini Live и аналоги).** Код сохранён (backend:
  `/realtime`, `app/providers/ai/gemini_live.py`; Android: `RealtimeVoiceController`),
  но в MVP режим скрыт: флаг `LIVE_VOICE_ENABLED = false` в
  `feature/voice/.../VoiceMode.kt` (решение пользователя 2026-10-09). Чтобы вернуть:
  подключить realtime через Model Gateway (M11), tools — через router M13,
  подтверждения, общую ленту и память; отдельный ключ провайдера; замерить
  задержку против каскада; затем включить флаг и вернуть пункт в настройки.
  *Когда:* после MVP (M60), если каскад окажется медленным.
- [ ] Выбор отвечающего устройства при нескольких терминалах.
- [ ] Офлайн TTS лучше системного (Piper, Kokoro-ru). Проверить лицензии
  (Silero — NC).
- [ ] Режим «старый телефон как колонка»: док-режим, always-on экран,
  дальнее поле.

## 5. Интеграции

- [ ] **Gmail:** чтение — restricted scope. Для публичного запуска нужна
  верификация Google и платная оценка безопасности (CASA). В testing mode
  до 100 пользователей, refresh token живёт 7 дней.
  *Когда:* если Gmail войдёт в публичный набор.
- [ ] **Telegram L1/L2:** TDLib на телефоне, затем сессия на сервере (см.
  раздел 3).
- [ ] Входящие события от сервисов (вебхуки) для реактивных сценариев.

## 6. Магазин и экосистема

**Когда возвращаться:** когда появятся внешние авторы.

- [ ] Публикация чужих плагинов: review, подписи releases, digest skills,
  поэтапный rollout, отзыв.
- [ ] Субреестр поверх официального MCP Registry (проверка namespace через
  GitHub/DNS).
- [ ] Изолированные executors (T2) для чужого кода: E2B, Daytona,
  Cloudflare Sandbox или gVisor на своей VM.
- [ ] Платные плагины, комиссия, выплаты авторам; правила App Store и
  Google Play.
- [ ] Builder App как эталонный тяжёлый плагин.
- [ ] Agent Card (A2A) для Mia, если понадобится федерация с внешними
  агентами.
