# S24 handoff

## Outcome

The reusable Android full-duplex audio core is implemented, integrated into the
Android `main` branch, and passes unit, lint, instrumented-APK build, full
Android regression, and mandatory physical-device gates. The device run on a
Samsung SM-S938B completed full-duplex capture/playback and all 20 repeated
resource-release cycles.

## Scope completed

- Added AudioRecord capture for signed PCM16 little-endian, mono, 16 kHz with
  fixed 20–40 ms frames and a contract-bounded 200–300 ms channel.
- Added streaming AudioTrack playback for PCM16 mono 24 kHz with a bounded byte
  jitter buffer, 100 ms maximum chunks, assistant/speech attributes, and
  transient audio focus.
- Added response-scoped playback, cancellation, pause/flush, stale/cancelled
  response rejection, capture-overflow shutdown, metrics, and idempotent
  release/restart lifecycles.
- Added format/effect/min-buffer capability diagnostics and opt-in AEC/noise
  suppression hooks.
- Added deterministic sine PCM tests plus a debug-only physical-device harness
  that performs full duplex and reallocates/releases AudioRecord and AudioTrack
  through 20 cycles on one reusable engine.

## Contracts produced or changed

- `DuplexAudioEngine` is the S25/S26/S27 entry point. It exposes bounded
  `capturedAudio`, `beginPlayback`, `offerPlayback`, `cancelPlayback`, stop and
  close lifecycle methods, capability diagnostics, events, and metrics.
- `MiaAudioFormats.Capture` is PCM16 mono 16 kHz; `Playback` is PCM16 mono
  24 kHz. The default capture frame is 40 ms/1280 bytes.
- `responseId` is mandatory for output. Chunks for non-current or cancelled
  responses are rejected and never queued.
- No backend/realtime schema or shared Gradle version catalog changed.

## Decisions

- Capture overflow stops that capture epoch and emits `CaptureOverflow` rather
  than accumulating stale audio; restart clears the prior epoch.
- Playback bounds bytes as well as chunk size, copies accepted arrays, and
  retains a bounded cancelled-response set to reject duplicated stale starts.
- AndroidX test dependencies remain module-local because the shared version
  catalog is outside S24 ownership.
