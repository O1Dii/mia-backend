## Outcome

ADR-0017 on the server. A user has many chats; each chat is one conversation with its own recent window and
summary, so the model never sees a neighbouring chat (memory, plugins, jobs, inbox, approvals stay account-wide).
`/v1/chats*` lists/creates/renames/pins/deletes chats, offers «Продолжить прошлый» and holds the retention setting;
`/v1/feed?conversation_id=` reads one chat and without it the most recently active chat (old clients keep working).
Voice runs may target any chat. A job started from chat A posts a result card into A and an inbox item. The Telegram
bot dialog is the chat «Telegram» (`/new` starts a fresh one). `GET /v1/now` lists active timers, alarms, focus
sessions and jobs with cancel hints. Retention deletes only old unpinned chats.

## API for M75 (web) and M76 (Android)

All endpoints: bearer or `mia_session` cookie; mutations need `Idempotency-Key` (16–128); `Cache-Control: no-store`.

- `GET /v1/chats?limit=1..100&cursor=` → `{items: Chat[], next_cursor}`; pinned first, then by activity.
  `Chat = {id, kind: chat|telegram, title|null, title_source: auto|model|user|null, pinned, pinned_at, created_at,
  last_message_at, last_assistant_at, preview (last message ≤120), preview_role}`. Bad cursor → 400 `invalid_chat_cursor`.
- `POST /v1/chats` body `{title?}` → 201 `Chat` (replayed key = same chat). Then send with `POST /v1/runs`
  `{profile: chat|voice, input, conversation_id: chat.id}`. Title appears after the first message (provisional),
  then the model's (refetch the list or the chat after `run.completed`).
- `GET /v1/chats/continue?within_seconds=300` (30..3600) → `{chat: Chat|null, within_seconds}` — chat whose last
  answer is younger than the window. Side key flow (M76): call `continue`, show «Продолжить прошлый» if non-null,
  create the new chat lazily (`POST /v1/chats` right before the first run) — an empty chat is removed after 24 h anyway.
- `GET /v1/chats/{id}`, `PATCH /v1/chats/{id}` `{title?: string|null, pinned?: bool}` (null title → automatic),
  `DELETE /v1/chats/{id}` → 204. Foreign/missing/hidden → 404 `conversation_not_found`.
- `GET|PUT /v1/chats/settings` `{retention_days: 30|60|180|null}` → `{retention_days, choices: [30,60,180,null]}`.
- `GET /v1/feed?conversation_id=&before=&limit=` → `{items, next_cursor, conversation_id}`; without the param = the
  default chat (`conversation_id` says which; null if the user has no chat). Cursor is bound to its chat (400).
  Result cards: `FeedItem.card = {type: job_result, job_id, status: succeeded|failed, title}`, `source: run_job`,
  `run_id: null`, `text`/`display` = the result. Render as a card with a link to the job/inbox item.
- `GET /v1/now` → `{server_time, items: NowItem[]}`; `NowItem = {kind: timer|alarm|focus|job, id, label, state:
  running|scheduled|paused|queued|waiting_approval, deadline_at, remaining_ms, duration_ms, started_at, plugin_id,
  installation_id, job_id, run_id, conversation_id, cancel}`. Cancel: `tile_tool` →
  `POST /v1/installations/{installation_id}/tiles/{tile_id}/tool-calls {name: "cancel", arguments}`; `job` →
  `POST /v1/jobs/{job_id}/cancel`. Count down locally; refresh on focus, after runs, or every ~30 s.
- Runs without `conversation_id` (old clients, Android voice today) go to the most recently active chat.

## Decisions

- `/v1/chats` instead of `/v1/conversations`: the legacy S-era router owns that path and Android still calls it.
- Default chat = most recently active `chat` (not Telegram); created race-free via the old `is_primary_feed` index.
- Job runs in a hidden `background` conversation; only the card reaches the source chat (OI-M74-002).
- Retention in the API lifespan, hourly, `SKIP LOCKED`; empty chats go after 24 h (OI-M74-004).
- Titles: provisional (first line, ≤60) at the first message; the model titles chats with ≤6 messages unless the user
  renamed; failures keep the provisional title.
