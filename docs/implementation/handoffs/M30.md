# M30 handoff

Branch `session/M30-web-chat`; `backend_head_commit` = last code commit, the handoff commit follows it.

## Outcome

Web работает на едином ядре: вход по cookie `mia_session`, чат на `/v1/runs` (SSE с переподключением) и ленте `/v1/feed`,
подтверждения в чате и на отдельном экране, магазин (согласие, OAuth-подключение, add-by-URL, обновление с повторным
согласием, удаление), подключения моделей на `/v1/model-connections`, голосовой ввод и озвучка на браузерных
`SpeechRecognition`/`speechSynthesis`. Все экраны на токенах и компонентах M33, проверены на 390/768/1440 px без горизонтального
скролла. Закрыт OI-M15-003 для web (привязка OAuth-потока к браузеру).

## Scope completed

- Клиент `/v1` (`lib/http.ts`, `api.ts`, `errors.ts`), SSE `followRun` (fetch-стрим, `Last-Event-ID`, до 6 переподключений, затем `GET /v1/runs/{id}`).
- Чат: лента с подгрузкой старых, ответы с markdown/`display` (text, card, app-fallback, link), шаги инструментов, подтверждения
  в ленте, подсказки `followups`, остановка (`cancel`), возобновление после перезагрузки (ждущие подтверждения и последний
  незавершённый run). Состояние чата живёт выше экранов (`ChatProvider`), переход в «Магазин» не обрывает run.
- Голос: микрофон в поле ввода (текст в поле, отправка вручную; «Отправлять сразу после диктовки»), «Озвучить/Остановить» у
  каждого ответа, автоозвучка `response.final.speech` после надиктованного вопроса, «Всегда озвучивать ответы» (`localStorage`
  `mia.voice.prefs`), браузер без распознавания: кнопка скрыта, подсказка.
- Подтверждения: `ApprovalCard` (summary, риск, параметры, Одобрить/Отклонить с `args_hash`), экран с историей, бейдж в навигации.
- Магазин: каталог (поиск, категории, ещё), страница плагина (скриншоты, согласие, отзывы), установка с точными `tools_digest`/`grants`,
  вход в аккаунт, `/store/connected`, add-by-URL, «Мои плагины» (обновление, отключение аккаунта, удаление), «Модели».
- Backend (минимум): cookie-принципал на `/v1/runs*` и `/v1/model-connections*`; привязка web OAuth-потока к браузеру.
- Playwright: 23 теста на настоящей сборке backend с подделанными внешними мирами (`web/tests/support/e2e_server.py`).

## Contracts produced or changed

- `openapi.yaml` (аддитивно): `cookieAuth` как альтернатива у 10 операций `/v1/model-connections*`; `startConnection` описывает cookie
  `mia_oauth_binding`. Runs уже наследовали глобальную security (bearer или cookie), поведение сервера теперь совпадает с контрактом.
- Поведение: web-старт OAuth-потока (cookie без `Authorization`) выставляет `Set-Cookie: mia_oauth_binding=…; HttpOnly; SameSite=Lax;
  Path=/v1/connections/callback; Max-Age=<flow TTL>`; колбэк без совпадающего значения → редирект `connection=error&code=connection_flow_invalid`,
  состояние сгорает. Значение выводится из `user_id` + `Idempotency-Key`, поэтому повтор запроса даёт ту же cookie. Android (bearer) не привязан.

## Decisions

- Маршруты через `history` (не hash): возврат OAuth приходит на путь `/store/connected` (`return_to`); отдельный маленький роутер `lib/router.tsx`.
- Web client ID Google — переменная сборки (OI-M30-001); вход «через хаб» POC не переносится (OI-M10-001).
- Привязка OAuth-потока — вариант (b) из OI-M15-003 (Lax-cookie), а не `complete` под сессией (a): не меняет контракт колбэка Android.
  Для Android остаётся OI-M30-002.
- Все вызовы `/v1` идут с `Idempotency-Key`; решение по подтверждению — детерминированный ключ `approval.id + решение + хвост args_hash`.
- Состояние run хранится на сервере; web после перезагрузки поднимает ждущие подтверждения и последний незавершённый run (нет API «активные runs»).
- Нет `incognito`-переключателя и вкладки «Новый диалог»: лента одна (M18).
- Тестовый backend (`e2e_server.py`) собирает продакшн-слои (auth, workspace, store, connections, router, approvals, runs, feed, models) и подменяет
  Google-верификатор, модель (сценарий по ключевым словам) и удалённый MCP+AS из `tests/catalog/remote_world.py`; в `/__e2e/*` — только тестовые ручки.
