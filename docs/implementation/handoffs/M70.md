# M70 handoff

Branch `session/M70-device-policy` (worktree `mia-helper-wt/M70`), 7 code commits + this handoff. Nothing merged.

## Outcome

ADR-0016 on the server. A run carries a **verified** device only (bearer → device of its refresh family; the app's
WebView → device bound at the M24 hand-off; a browser never), and its requester is recorded. A run from another client
sees the user's phone tools; each call goes through one policy `allow | ask | deny` over (capability, requester, target,
scope). `ask` = an M13 approval with `device_consent` that **only the app on the target phone** may decide (push with
actions), the run waits ≤ 120 s (`waiting_for_device`); deny / timeout / offline / disabled give distinct error codes the
model is told to report plainly. Consent covers the run (not external acts) or, if chosen, this requester for 30 days
(ends on revoke, expiry or the browser session's end). Device results lose phone numbers before anything else sees them;
the phone's settings get grants, capability switches and an access log. `builtin.alarm` no longer sets the Clock alarm
implicitly. DoD e2e passes on memory and Postgres run stores.

## Decisions

- **Requester verification at `POST /v1/runs`** (not in the router): a browser could otherwise claim the phone's
  `device_id`. The claim is replaced by the verified device or dropped; the existing consumers (memory, Telegram host,
  router same-device path) keep working unchanged.
- **Consent reuses M13 approvals**: the engine's wait, `waiting_approval` status, cancel and budget handling apply;
  `waiting_for_device` is `device_consent.waiting_for = "device"` on the approval (no new run status in M73's scope).
- **Push delivery** (`GET /v1/devices/{id}/tool-calls` + FCM wake, no arguments through FCM) for any device that did not
  start the run; `device_tool.call` is still published into the requesting run for display.
- Target = phone that last declared tools (declarations now persisted); no silent fallback (OI-M70-004).
- Minimization in the channel and the router (contact phones never reach memory, events or the model).
- Alarm preference via `memory.remember`; tool descriptions untouched to keep `tools_digest` (OI-M70-007).
