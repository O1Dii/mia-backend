# M10 handoff

Branch `session/M10-unified-accounts`; `backend_head_commit` = last code commit, the handoff commit follows it.

## Outcome

Web (HttpOnly cookie) and Android (bearer) sign in to one `users` row keyed by
the verified Google `sub`; one `RequestAuthenticator` yields the same `user_id`
and personal workspace for both. Installations, plugin state, dashboard tiles
(desktop + mobile layout, settings, `state_version`) and reviews live in
Postgres behind `/v1/workspace`, `/v1/installations*`, `/v1/dashboard*` with
`expected_version` compare-and-swap (409) and `Idempotency-Key` replay. A
read-only, idempotent web-SQLite import with an owner check moves POC data.
Cross-tenant negative tests, migration up/down and model parity pass.

## Contracts produced or changed

`contracts/mvp/v1` not edited (see requested changes). Implemented, all under `bearerAuth` **or** cookie `mia_session`:

- `POST /v1/auth/web/nonce` → 201 `{nonce, expires_at}` + cookie `mia_web_nonce`; `POST /v1/auth/web/google` `{credential}` → `{user, expires_at}` + cookie `mia_session`; `POST /v1/auth/web/logout` → 204. All take `Idempotency-Key`.
- `GET /v1/workspace` → `{id, name, owner_user_id, layout_version}`.
- `GET|POST /v1/installations`, `GET|PATCH|DELETE /v1/installations/{id}` (`?delete_data=true`), `GET|PUT /v1/installations/{id}/state`. `Installation` = contract fields + `source`, `grants`, `tools_digest`, `state_version`, `created_at`, `updated_at`. `POST` body = contract `CreateInstallationRequest` (catalog `{plugin_id, version, tools_digest}` or `{custom_mcp_url}`).
- `GET|PUT /v1/dashboard`, `PATCH /v1/dashboard/tiles/{tile_id}`. Tile = contract fields (`size`/`position` = desktop) + `mobile {size, position}` (defaults to desktop), `settings`, `state_version`.
- **Version semantics:** GET returns the current version (`expected_version` for the dashboard, `state_version` elsewhere). Send it as `expected_version`; success increments it by 1 (state starts at 0 = absent). Stale → 409 `{"code":"version_conflict","details":{"current_version":N}}`; refetch and reapply. Uninstalling a plugin with tiles bumps the dashboard version.
- **Idempotency:** per workspace, 24 h. Same key + same body → stored response replayed (no second increment); same key + other body → 409 `idempotency_conflict`.
- Errors: new `version_conflict`, `tools_digest_mismatch` (409); reused `resource_not_found` (missing **or foreign** → 404), `conflict`, `idempotency_conflict`, `permission_denied` (403 cross-site cookie mutation), `validation_error`, `authentication_required`, `invalid_credentials`, `service_unavailable` (OI-M00-001).

## Decisions

- One personal workspace per user (`uq_workspaces_owner_user_id`), created lazily on first request; `user_id`/`workspace_id` travel as strings (`ToolContext`).
- Catalog is a port (`PluginCatalog`); default empty catalog → catalog installs 404 until M14/M15 plug theirs in. Install requires the catalog `tools_digest` (consent pinning). Re-install of the same version/digest returns the existing row; other versions → 409 `conflict` (upgrade flow is M15).
- Custom MCP URL install: plain HTTPS only, status `needs_consent`, `plugin_id = custom.<sha256(url)[:16]>`; no network access in M10.
- `PluginState` is keyed by `(workspace_id, plugin_id)` so it survives reinstall; `delete_data=true` purges it.
- Import is insert-if-absent with deterministic UUIDv5 keys, so reruns are no-ops and never overwrite Postgres changes; `owner_mismatch` blocks moving a legacy account to another user. Hub accounts (`hub:<uuid>`) need `--identity-map` (OI-M10-001). Not imported: sessions, challenges, audit, BYOK, SDK grants, anonymous data.
- Web hub login (`/api/web/auth/hub`) not ported: no Google `sub`.

## Known limitations

- Workspace routes have no per-user rate limit (auth routes do).
