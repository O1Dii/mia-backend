# M15 handoff

Branch `session/M15-store-connections`; `backend_head_commit` = last code commit, the handoff commit follows it.

## Outcome

The store cycle works end to end on Postgres: an administrator publishes a package (`python -m cli.mia_plugin`), users find it in
the catalog, see the consent screen, install it with the digest and grants they saw, connect their account over OAuth, update with
re-consent when permissions grow, and uninstall with the provider tokens revoked. All six M14 builtin plugins publish. A custom MCP
server added by URL (with OAuth against a test authorization server: PKCE S256, resource indicator, protected resource metadata,
dynamic registration, rotating refresh, RFC 7009 revocation) is probed, consented and called through the M13 router.

## Decisions

- Publishing is CLI only (runs on the backend host with its environment); no upload API. The image has no `contracts/` (OI-M15-004).
- Installs through the store echo `tools_digest` + every grant (`POST /v1/plugins/{id}/install`); M10 `POST /v1/installations`
  stays (digest only; grants are derived from the manifest, also for builtins through `CompositeCatalog`).
- Custom MCP: probe (`GET /discovery`) -> connect if the server answers 401 -> consent. Every tool is `write_external`; names the
  manifest grammar cannot hold are skipped (`skipped_tools`). The digest covers all listed tools, so a changed description blocks.
- OAuth: public client, PKCE S256 mandatory, `resource` on authorize/token/refresh, endpoints must be https on the issuer host,
  the single-use state is burnt before the code exchange, refresh serialized per connection (lock + `FOR UPDATE`) with rotation,
  a rejected refresh -> connection `expired` and installation `needs_connection`, uninstall/disconnect revoke refresh and access token.
- Upgrade revokes tokens only when the remote URL changed, and only after the update committed.
- Releases are immutable; republishing the same content is a no-op, different content is `release_exists`; `yank` hides a version
  from the catalog and new installs, installed copies keep running (router source reads any status).
- Hygiene: `tests/tools/helpers.py::Clock` started at a fixed 2026-10-09T12:00Z, so the Postgres approval round trip expired after
  12:02Z that day (M13 test, red at baseline now); it follows the wall clock.
