# M50 handoff

Branch `session/M50-mia-oauth`; `backend_head_commit` = last code commit, the handoff commit follows it.

## Outcome

Third-party apps sign in with Mia (OAuth 2.1 AS: authorization code + PKCE S256, CIMD clients, rotating
refresh with reuse detection, RFC 7009 revocation, OIDC ES256 ID tokens with pairwise `sub`) and use the
user's model through `/v1/chat/completions`, `/v1/responses` and `/v1/models` as `Run(app)`, with memory
context injected only under `memory.context` (never returned raw), Mia tools under `tools.use:<plugin>`
(approvals as usual) and a monthly spend limit per app. `/mcp` makes Mia a Streamable HTTP MCP server whose
tools follow the token's scopes. The OpenAI Python SDK and LiteLLM (in process and over a real socket) work
with `base_url` = Mia; JS and Python SDKs are generated from OpenAPI. Web consent page is a separate entry.

## Scope completed

- AS endpoints: `/.well-known/oauth-authorization-server` (= `/openid-configuration`), `/oauth/authorize|token|revoke|userinfo|jwks.json`, PRM `/.well-known/oauth-protected-resource[/mcp]`.
- Consent + «Подключённые приложения»: `/v1/oauth/requests/{handle}` (+`/decision`), `/v1/apps`, `/v1/apps/{id}` (GET/PATCH/DELETE), `/usage`, `/access-log`.
- `Run(app)` (`app/modules/oauth/apprun.py`, subclass of the M12 `RunExecution`): app messages, no feed, incognito, client tools passthrough, Mia tools, budget per step.
- `/mcp`: `memory.search` (`memory.read:<cat>`), `memory.suggest`, installed plugin tools via the router.
- SDKs `sdk/python` (`mia-sdk`, async) and `sdk/js` (`@mia/sdk`, Node ≥ 22 / browsers), consent page `web/oauth.html`.

## Decisions

- No Authlib: its AS needs a framework integration FastAPI lacks; the AS here is small and audited by tests (no new runtime dep).
- Public clients only (`token_endpoint_auth_method: none`, Basic → `invalid_client`); CIMD `client_id` ≤ 255 chars (fits `source_ref`).
- Errors before the redirect URI is verified are shown (400 JSON), never redirected; after that redirected with `state` and `iss`.
- Consent request binds to its first signed-in viewer; decision needs `Idempotency-Key` (same key replays, other → 409).
- Grant scopes are replaced on re-consent; every request uses token scopes ∩ live grant scopes (PATCH `remove_scopes` applies at once).
- `memory.context` categories exclude `health`/`finance`; defaults = the other five. App runs: incognito, no feed, no Mia persona.
- `/mcp`: stateless JSON transport, bearer-only (no Host allow-list: breaks behind nginx and adds nothing with bearer auth); plugin output
  stays framed `<tool_result trust="untrusted">`; `write_external` waits for the user's approval.
- `memory.context` alone exposes no MCP tool; raw reads only via `memory.read:<cat>`, logged `actor=app`.
- Forced test edit: M00 governance test assumed one exempt endpoint; `/v1/responses` is required by the card and cannot take a key.

## Known limitations

- No rate limit on `/oauth/*`; RFC 8414 discovery for an issuer with a path needs nginx rules (OI-M50-005).
- Spend: estimated when the provider gives no price; parallel requests may overshoot by one step each (OI-M50-004).
- The model may paraphrase injected memory in its answer (OI-M50-006). Provider `provider_state` of app-supplied assistant tool calls
  is not replayed (apps send plain OpenAI messages). A step mixing app tools and Mia tools returns only the app's calls.
- Refresh reuse detection: two concurrent refreshes with one token revoke the family (by design).
- Codex cross-review of the security diff (`app/modules/oauth/**`, `app/api/mcp_server.py`) is recommended per §3 (not run).
