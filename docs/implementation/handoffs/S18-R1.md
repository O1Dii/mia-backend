# S18-R1 handoff

## Outcome

The credential-gated provider smokes had nowhere to execute and had been
skipping since W3. They now run in a dedicated verification image, and the Live
smoke passes against the real API for the first time. The release image is
unchanged: still no test runner, still no tests, still unprivileged.

## Why it mattered

The runtime image ships no pytest on purpose, and `.dockerignore` keeps `tests`
out of its build context entirely — both good properties. The unintended
consequence was that `tests/providers/test_gemini_live_smoke.py` could not run
anywhere, so it reported SKIP in every gate from W3 onward.

Three defects that only real cloud traffic reveals therefore survived to a
physical device session: [S17-R1](S17-R1.md) (tool schema rejected by both
Gemini surfaces), [S16-R1](S16-R1.md) (transcript continuation) and
[S13-R1](S13-R1.md) (tool continuation rejected by Gemini 3.x). A smoke that
cannot run is worse than no smoke: it reads as coverage.

## A trustworthy signal

The first runs exposed a flaw in the smokes themselves. Under throttling they
failed with `provider_rate_limited` while the assertion message blamed a missing
`thought_signature` — confidently pointing at the wrong cause, which is the worst
thing a gate can do.

`provider_rate_limited`, `provider_timeout` and `provider_unavailable` now skip
with the reason printed by `-rs`: they say nothing about whether MIA builds a
request the API accepts, which is the only question these smokes exist to answer.
Any other `ProviderError` is a genuine rejection and fails. So a throttled run
neither cries wolf nor passes silently — and a skip is visible, never inferred
as coverage.

## Configuration

Names only. `MIA_ENV_FILE` selects the environment file (default `.env`),

## Decisions

- A separate `Dockerfile.test` rather than a stage in `Dockerfile`: S18 audited
  the release image and deliberately excluded tests from its build context.
  Adding a stage would have meant un-ignoring `tests`, weakening a property
  somebody chose on purpose. Both files read the same `pyproject.toml` and
  `uv.lock`, so the duplication cannot cause dependency drift.
- The image runs as the same unprivileged uid as the runtime image, so nothing
  about it invites reuse as a base for anything deployable.

## Known limitations

- The Live smoke cannot distinguish throttling from a genuine rejection: the
  adapter sanitizes every transport failure to one fixed message, so the
  classification added to the text smokes has nothing to key on there
  ([OI-W6-003](../OPEN_ISSUES.md) covers the underlying opacity).
- At the time of writing the account was rate-limited, so the two text smokes
  skipped on the final runs. They were observed passing earlier in the session,
  and [S13-R1](S13-R1.md) records the model comparison they encode.
