## Decisions

- Шаблон — remote-плагин с `auth: "none"`, а не declarative: declarative не вызывает внешний REST (M42), а card
  требует MCP. Сервер шаблона лежит в `plugins/_template/server/` и в релиз не попадает (как у M42).
- Тесты в `tests/plugin_template/`, а не в `plugins/_template/tests/`: pytest `testpaths = ["tests"]`, mypy `files = ["app", "tests"]`.
- Публикация шаблона в тесте идёт через `build_store(require_auth=False)`: шаблон объявляет `auth: none`, токен не отправляется.
- Ссылочная проверка оформлена как тест (`tests/plugin_template/test_docs_links.py`), чтобы её можно было повторять.
  Она уже поймала битую ссылку на каталог (исправлено).
- Документация не описывает `app/web_poc` и формат v2 как текущий путь; формат POC помечен как не используемый для новых плагинов.
- Плитки в руководстве рекомендуются через `bundled`; `ui://` сервера описан как ограничение (OI-M43-002).
- `auth: mia_token` помечен как «не используйте»: consent требует подключения, которого для него нет (OI-M43-004).
- SDK не публикуются в индекс; документированы установка из репозитория и тестовые команды (OI-M43-003).

## Known limitations

- Шаблон хранит заметки в памяти процесса (демо); настоящий сервер должен сопоставлять токен с пользователем.
- Тест публикации использует тестовый MCP-сервер, а не настоящий HTTPS-хост.
- Руководство описывает правила валидации по коду на момент сессии; при изменении `validation.py` или `grants.py` его нужно обновить.
- `README.md` шаблона попадает в релиз как обычный файл пакета: `package.py` сохраняет все `.md`.
