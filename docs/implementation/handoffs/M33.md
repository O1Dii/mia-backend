Branches `session/M33-design-system` in both repos. `backend_head_commit` is the last code/doc commit before this handoff commit.

## Outcome

One visual language for web and Android from a single W3C token file: `design/tokens/mia.tokens.json` generates `web/src/styles/tokens.css` and Android `MiaTokens.kt` (drift test PASS). Web screens got the new skin (dark primary, full light theme, aurora background, layered glass, large radii, spring motion, touch targets 44 px), Android got `MiaTheme` plus glass surface (no-blur fallback for API < 31), buttons, input with mic button, bubble, `display` card and orb. A style page and screenshots (web in both themes at 390/768/1440 px without horizontal scroll, Android gallery) are ready for review (UC-MW3-1).

## Decisions

- Theme: web follows the system (`prefers-color-scheme`), dark when no preference; manual override by `data-theme`. No toggle UI yet (needs `App.tsx`, out of scope).
- Palette keeps the existing lime brand accent; light theme uses a dark olive for accent text (4.5:1+) and the lime only as a fill.
- `styles.css` migration was mechanical, not a rewrite: neutrals map to tokens (bg, surface-1..3, border, text roles, accent/on-accent); other literals (plugin-specific tints) became `light-dark(<derived light>, <original>)`; the plugin art and the hero spheres keep literal colors (illustrations). Radii 9–32 px were raised to the token scale. The skin block at the end adds glass/blur/rim/depth, pill buttons, 44 px targets, themed toasts (sonner CSS variables override `theme="dark"` in `main.tsx`).
- Android glass: `Modifier.blur` blurs the surface's own tinted layer (API 31+); true backdrop blur needs a library (OI-M33-002). API < 31 uses opaque `surfaceSolid`.
- Reduced motion: web via `prefers-reduced-motion` (global rule already existed) plus component rules; Android via `Settings.Global.ANIMATOR_DURATION_SCALE == 0` observed in `rememberSystemReducedMotion()`; components snap and the orb shows level by glow only.
- Screenshot tests do not use a screenshot library: Robolectric native graphics draws the decor view to a PNG (`captureToImage` times out without PixelCopy). They assert non-blank, theme luminance and semantics, not pixel equality (no golden files); PNGs land in `core/designsystem/build/mia-screenshots/`.
- Backend/web verification did not require Postgres/Redis (no backend code touched); the full DB suite was not rerun.

## Known limitations

- Web needs a 2024+ browser: `light-dark()` (Chrome 123, Safari 17.5, Firefox 120) and `color-mix()`.
- Android uses the system sans font; the Manrope token is carried but not bundled.
- The Android drift test is skipped unless `mia.tokens.json` is reachable (it is after the integrator merges M33 into main, via the default sibling path).
- Fonts load from Google Fonts on web (existing behavior).
