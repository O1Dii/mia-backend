## Outcome

ADR-0016 on the phone. A request of another client (web on a computer, another device) for something on this phone now reaches the owner: a consent
push opens the sheet «<клиент> просит: <возможность>» (or, in the background, a high-priority notification with «Разрешить» / «Отклонить» that
answer without opening the app and need an unlocked phone); the sheet offers «Разрешить сейчас» (this request), «Всегда разрешать: <клиент>» (30 days,
only when the server offers the persistent scope and never for external acts) and «Отклонить», with the data the model will see and a countdown.
Calls queued for the phone by push delivery run through the same device-tool channel as the app's own and post their results. Settings has
«Доступ с других устройств»: per-capability switch (others may ask / never), permanent permissions with «Отозвать», and the request log.
A fired cloud alarm or timer rings as a Mia alarm: an alarm-sound notification that repeats until dismissed plus a full-screen screen over the
lock screen. The WebView now keeps only Mia's own paths under the web base (`/mia/…`).

## Scope completed

- **Consent flow** (`:feature:consent`, new): `ConsentPresenter` (loads `GET /v1/approvals/{id}` when opened by id, countdown to `expires_at`,
  decisions with `args_hash` + `scope`, stable `Idempotency-Key` per answer, outcomes allowed / allowed-for-client / denied / expired / closed,
  errors: no connection → stays open, changed request → re-read, scope no longer offered → re-read) and `ConsentScreen`. Route `consent/{approvalId}`.
- **Push** (`core/push`): `device_consent` → sheet if the app is on screen (`PushEnvironment.foregroundConsent`, set by `MainActivity` between
  `onStart`/`onStop`), else `ConsentNotifier` (channel `mia_consent`, HIGH; actions through `ConsentActionReceiver`, `setAuthenticationRequired`
  on Android 12+, `VISIBILITY_PRIVATE`, times out at the deadline; a failed send leaves a notification that reopens the sheet).
  `device_tool_call` → `PushEnvironment.deviceCallRunner`. `inbox_item` of `builtin.alarm:*` / `builtin.timer:*` → `AlarmNotifier` + `MiaAlarmActivity`.
- **Device tools** (`core/devicetools`, `core/network`): `DeviceCallSync.drain()` (`GET /v1/devices/{id}/tool-calls` → `DeviceToolChannel.handleQueued`,
  skipping call ids already run from the own stream or an earlier fetch). Triggered by the wake-up push, when the chat opens, and every 4 s while a
  WebView screen is open.
- **Settings** (`feature/settings`): `DeviceAccessPresenter`/`DeviceAccessScreen` (route `settings/device-access`), section «Будильники и таймеры Мии»
  («Проверить звонок», full-screen permission hint + system screen on Android 14+), entry «Доступ с других устройств».
- **Mia alarm** (`core/push`): channel `mia_alarm` (HIGH, `USAGE_ALARM` default alarm sound, vibration, public on lock screen), notification
  with category ALARM, `FLAG_INSISTENT`, ongoing, full-screen intent, «Выключить», 5-minute limit; `MiaAlarmActivity` (plain views, over lock screen,
  `showWhenLocked`/`turnScreenOn`, own task, not in recents). Cancelling the notification stops the sound.
- **WebView** (`feature/web`): `WebNavigationPolicy` allows origin AND path prefix; `WebSurfaceLoader` refuses a redeem URL outside the prefix.
- **API clients** (`core/network`, additive): `DeviceAccessApi`/`OkHttpDeviceAccessApi`, `DeviceAccessModels`, `Approval.deviceConsent`,
  `ApprovalsApi.decide(..., scope)` (default-implemented overload, existing implementers untouched).

## Decisions

- Consent in the foreground is the sheet itself, in the background a notification (OI-M71-003); «Разрешить» in the notification is only this request, «Всегда» only in the sheet.
- Timers ring like alarms (OI-M71-002). Sound belongs to the notification (alarm-usage channel, insistent), the screen is a view that cancels it: the ring works even when the screen cannot be shown (OI-M71-006).
- The alarm screen uses plain views (no Compose/nav/sign-in) so it opens immediately from a full-screen intent.
- `ApprovalsApi.decide` got a default-implemented scoped overload instead of changing the interface, so `MockMiaBackend` and other fakes compile unchanged.
- The queue of device calls is read on push, when the chat opens and every 4 s while a WebView is open (WebView runs are queued; the wake-up push may not arrive).
- A redeem URL outside the web base path is refused (strict form of OI-M62-T1-001); the backend returns the prefix in `redeem_path`.
- Notification permission asked once for push, timers, alarms and consent (OI-M71-010).
