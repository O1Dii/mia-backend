# M22 handoff

Android branch `session/M22-cascade-voice` (7 commits on `522c517`), coordination branch
`session/M22-coordination` (this file + `## M22 inbox`). Backend code unchanged.

## Outcome

Voice now works with any model: local VAD → on-device GigaAM STT (M21) → `POST /v1/runs`
(`profile=voice`) → SSE events → system TTS sentence by sentence, `speech.ack` spoken at once,
`display` card + follow-ups on screen, approvals on an Approval screen. New speech while a turn
is active is a barge-in (TTS stop + `POST …/cancel`). The cascade is the default voice mode;
Gemini Live stays selectable in Settings. Device gate on SM-S938B passed: 20/20 turns, end of
speech → first sound p50 804 ms / p95 836 ms (scripted 0 ms model), barge-in, reconnect with
`Last-Event-ID`, approval approve/deny/expire from voice.

## Decisions

- Cascade is default; Live kept untouched (`RealtimeVoiceController`), chosen via `VoiceModeStore`.
- Barge-in = any new user speech while a turn is active (transcribing, thinking, speaking); TTS
  playback raises the VAD threshold (`playbackSpeechRms`). One mechanism (local stop + cancel).
- While an approval is pending the mic is ignored; the user decides on screen or taps Stop
  (cancels the run). Approval prompt = `summary` + «? Подтвердите на экране.».
- OI-M12-004 decision: speak the server's `speech.ack.text` via TTS (no earcon); keep 1500 ms.
- `create` is not cancelled midway; a run started under a barge-in is cancelled right after.
- Runs/device tools use the sign-in installation id (`KeystoreSessionStore.deviceId()`).
