# S22 handoff

## Outcome

Android has a Room-backed, account-isolated conversation/history cache with REST
keyset pagination, canonical server-ID/sequence merge, durable optimistic messages,
same-key retry, and process-restart reconciliation. Android implementation worktree:
`/private/tmp/mia-helper-android-S22`, branch `session/S22-history-cache`.
Coordination worktree: `/private/tmp/mia-helper-S22-coordination`.

## Scope completed

- Room entities, DAO, exported version-2 schema, and tested 1→2 migration.
- Server REST pagination and SSE completion/replay parser.
- Transactional entry merge, sequence conflict rejection, and pending-to-canonical
  reconciliation by server turn ID (never by text/time).
- Durable idempotency key stored before send, preserved through network failure and
  process restart; acknowledged retries refresh history without resending.
- Cached list data source for S23; no app/UI/root-file ownership changes.

## Contracts produced or changed

- New `ConversationCache`, `RoomConversationCache.open(context, userId)`,
  `ConversationRemote`, `HttpConversationRemote`, and `CachedConversationRepository`.
- `CachedConversationRepository` keeps the existing `ConversationRepository`
  `StateFlow<List<Conversation>>` interface; `history()` returns canonical entries
  ordered by server sequence plus separate optimistic pending entries.
- No backend/OpenAPI/realtime contract was changed. Opaque REST cursors are never
  decoded or constructed on Android. Transcript kind, modality, and delivery status
  are persisted unchanged; OI-ARCH-005 remains for S31.

## Data and migrations

- Room schema v2 tables: `conversations`, `entries`, `pending_messages`,
  `sync_cursors`. Unique `(conversationId, sequence)` and pending
  `(conversationId, idempotencyKey)` indices; canonical entry server ID is PK.
- `MIGRATION_1_2` adds durable pending/cursor tables without wiping v1 history;
  Robolectric migration test preserves seeded conversation/entry rows.
- `lastSequence` is persisted, but reconnect currently re-traverses opaque pages
  from the beginning because S14 exposes no final-page resume cursor.

## Decisions

- Keep the server authoritative and never infer entry identity from text/time.
- Cache one database per authenticated UUID; S23 must recreate the repository on
  account changes rather than reuse a token-switched cache.
- Hide conversations absent from a fully completed server list without erasing
  their cached entries or pending operations. A failed partial fetch does not hide.

## Open issues / known limitations

- OI-S22-001: full keyset traversal on reconnect is correct but can be costly for
  long histories; additive server-issued incremental sync cursor is recommended.
- OI-ARCH-005 remains open; cached output transcripts are not promised to be
  exact authored text.
- A pending operation against a server-deleted conversation remains visible and
  retryable until a higher-level UI resolves the 404; S23 should expose that state.
