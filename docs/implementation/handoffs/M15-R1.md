## Root cause (test server, 2026-10-10)

Linear added by URL stored a generated manifest with all 76 tools; `parse_manifest` allowed 1..64, so
`PluginRegistry._resolve` logged a warning and returned `None` on every run — the router never saw the installation while
«Мои плагины» said «Работает». The JSON log formatter allow-listed only 15 event names, so every other event (including
`plugin_manifest_invalid`) was printed as `redacted_event`, and `reason` (a sentence) was dropped too.

## Decision and rationale

- **One explicit limit, derived from the model.** OpenAI-compatible providers reject more than 128 function tools per
  request, and one request carries core tools (`background.*`, `schedule.*`, `memory.*`), `skills.load`, the device's tools
  and every plugin. `app/modules/plugins/registry/limits.py`: `MODEL_TOOL_LIMIT = 128`, `HOST_TOOL_RESERVE = 32` (≈20 today),
  `PLUGIN_TOOL_BUDGET = 96` (all active plugins of a user together), `MAX_PLUGIN_TOOLS = 96` (one installation). The same
  96 is used by `mia.json` schema (`maxProperties` 64 → 96, a relaxation), `parse_manifest`, the add-by-URL probe/consent
  and the registry. Raising only the per-plugin cap (e.g. 128) would let Linear + builtins exceed the provider limit and
  break every chat run, so the budget is shared.
- **The user picks the tools of a server added by URL.** Discovery returns `tool_limit` (96 minus the other active
  plugins' tools) and `selected` per tool: a server with ≤ 24 tools is fully ticked; a larger one starts without
  destructive tools (`delete_`, `archive_`, `remove_`, …), capped at the limit by rank (reads, main writes, other,
  destructive). Consent takes optional `tools` (omitted = all usable, refused with 422 `validation_error` when over the
  limit); the stored manifest holds only the chosen tools, the digest still covers every server tool (router unchanged).
  «Мои плагины» → «Выбрать инструменты» reopens the same screen with the current choice.
- **Nothing disappears silently.** The registry returns an installation it cannot offer with status `needs_attention`
  and `problem` (`manifest_invalid` + `reason` = `ManifestError.code`, `manifest_missing`, `manifest_mismatch`) and a
  fallback manifest with the declared tool names, so the router refuses a call by name with `tool_not_active` instead of
  `tool_not_found` (router code unchanged: non-`active` status → `tool_not_active`). Past the budget, later installations
  are trimmed (`problem = tool_budget`, destructive tools first) or, with no room left, `needs_attention`. Every case logs
  a readable event with `plugin_id`/`installation_id`.
- **Health endpoint instead of a DB status** (no migration, no change to the installations enum/M10 code):
  `GET /v1/installations/{id}/health` → `state` `ok|limited|needs_attention|needs_connection|needs_consent|disabled`,
  `problem` (+ `tools_changed`, `server_unavailable` from a live `tools/list` and digest check), `tools`, `declared_tools`,
  `tool_limit`. «Мои плагины» calls it per installation: «Требует внимания» + reason, «Инструментов: N (из M)».
- **Logs:** an `app.*` logger record whose message is a snake_case literal without `%` arguments is emitted with its name;
  sentences, messages with arguments and library loggers stay `redacted_event`. New typed fields: `plugin_id` (plugin-id
  pattern), `tool` (dotted tool-name pattern), `kind` (token), `installation_id`/`run_id` (UUID), `tool_count`/`limit` (int).

## What happens to the test server's Linear installation on deploy

`custom.ufb39103c7d2edac` keeps its manifest, digest, grants and OAuth connection; no re-add, no migration.

1. The 76-tool manifest now parses (≤ 96) and the router offers it again on the next run.
2. If the user's other active plugins declare ≤ 20 tools, all 76 Linear tools reach the model (`health.state = ok`).
   Otherwise Linear (the latest installation) is trimmed to `96 − others` tools, destructive ones dropped first; «Мои
   плагины» shows «Инструментов: N из 76» and a note; the log has `plugin_tools_over_budget` with `plugin_id`,
   `tool_count=76`, `limit`. «Выбрать инструменты» lets the user choose which ones fit.
3. If Linear's `tools/list` changed since consent, the router blocks it as before (`plugin_tools_digest_mismatch`, now
   readable); «Мои плагины» shows «Требует внимания — Сервер изменил свои инструменты» → «Выбрать инструменты» re-consents.
4. Every Linear tool stays `write_external` (each call asks for approval), as designed in M15 (OI-M15-002).

## Known limitations

- The budget counts manifest tools of active installations for every profile (voice/app see fewer); conservative.
- Health probes remote servers on each «Мои плагины» load (one `tools/list` per active installation, bounded by
  `TOOLS_LIST_TIMEOUT_SECONDS`).
- Default selection uses the leading verb of the tool name (MCP `readOnlyHint` is not read; see OI-M15-002).
