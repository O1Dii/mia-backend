# M17 handoff

Branch `session/M17-memory-ledger`; `backend_head_commit` = last code commit, the handoff commit follows it.

## Outcome

`MemoryService` implements the `MemoryProvider` port and is wired into the run engine. Facts, people and
preferences are sealed per user (M11 `KeyVault` DEK, AES-GCM, AAD per record); Postgres FTS runs over a
blind index (HMAC of word stems in a `tsvector`). The model writes through `memory.remember` (→ *suggested*,
`memory.suggested` event; auto-save only for allowed non-sensitive categories) and finds people through
`people.resolve` (memory first, then `device.contacts.search` via `DeviceToolChannel`), seeing only
`person:<id>` / `contact:<n>` with name and relation. All DoD items pass through the real engine on Postgres:
«Запомни, что Яна — моя жена» → suggested → confirm → `people.resolve("Яна")` → `person:<id>`; no phone in any
assembled model request; incognito writes nothing; export/import; crypto-shred.

## Scope completed

- Ledger tables + migration; `Fact`/`Person`/`Preference` in `memory.schema.json` form; source, sensitivity,
  scope, `last_used_at`; person drafts on suggested facts become `Person` rows on confirm (merge by name).
- Context for runs: pinned `profile` facts (≤5, non-sensitive) + top FTS facts + people named in the query,
  all through `minimize()` (phones, e-mails, @handles, long ids removed; dates kept).
- Core tools `memory.remember` (write_reversible, voice) and `people.resolve` (read, voice, 15 s).
- Incognito: the tool refuses (`memory_incognito`, checked via `runs.incognito`), engine already skips context.
- API `/v1/memory*` (contract paths + additive ones), access log without content, idempotent creates/import.
- Export zip (`memories/<category>.md`, `people.md`, `preferences.md`, `suggested.md`, `memory.json`) and JSON;
  import Markdown/text/JSON → review queue (suggested, source `import`, batch id).
- History retention sweep (`30d`/`1y`/`forever`/`none`) + incognito-run purge (1 h); `shred_account`.

## Decisions

- Encryption + FTS: blind index (`t` + 24 hex of HMAC-SHA256(sub-key of DEK, stem)), `array_to_tsvector` and
  a quoted `tsquery` cast, so nothing is normalized or readable server-side.
- Reads never create a DEK (`existing_keys`); a user without a DEK has no memory.
- `people.resolve` asks the phone only when memory has no match; contact details stay in a per-run in-process
  cache, stored only via `memory.remember{person.contact_ref}` + user confirmation (source `turn`).
- In incognito `people.resolve` still reads memory (to address a message) but updates no `last_used_at`;
  the read is audited. `memory.suggested` text is the user's own content on their own stream.
- `forget_all` keeps the DEK (model connection secrets share it); `shred_account` destroys it.
