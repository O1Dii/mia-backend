## Решение (OI-M60-001, вариант b, пользователь 2026-10-11)

В профиле `voice` read-вызовы (`descriptor.risk == "read"`, классификация роутера) одного шага модели делят
**одну** единицу бюджета `RUN_VOICE_MAX_TOOL_CALLS` (по умолчанию 2), до 4 чтений на шаг. Пятое чтение шага не
выполняется: модель получает `{"status":"skipped","error":"parallel_read_limit"}`. Запись (`write_*`) и любой
не-`read` риск считаются по одному. Шагов по-прежнему ≤ 3, бюджет 2, так что ADR-0011 (~6 с до первого звука)
сохранён по смыслу; замер на живой модели — UC-M60-8.

## Изменения

- `app/core/config.py`: `run_voice_max_parallel_reads` (`RUN_VOICE_MAX_PARALLEL_READS`, по умолчанию 4, 1..8);
  `.env.example` — имя переменной.
- `app/modules/runs/profiles.py`: `ProfileLimits.max_parallel_reads` (по умолчанию 1 — chat/job/app без изменений),
  подключено из `Settings` только для `voice`. (Файл вне перечня write scope карточки, но это место, где живут лимиты профилей.)
- `app/modules/runs/engine.py`: `budget_used` (единицы бюджета) отдельно от `tool_calls` (выполнено вызовов,
  уходит в `run.completed`); `step_reads` сбрасывается на каждом шаге; `offer_tools` смотрит на `budget_used`.
- `docs/adr/0011-*.md`: поправка от 2026-10-11 с причиной.
- Тесты: `tests/runs/test_engine.py` (3 чтения = 1 вызов и бюджет на следующий шаг; пятое чтение отклонено;
  запись считается отдельно; чтение после исчерпания бюджета пропущено; chat не группирует),
  `tests/runs/test_wiring.py` (значения из `Settings`), `tests/e2e_mvp/test_s02_today.py` (strict xfail снят и тест
  проходит; старый тест «два источника» заменён на проверку нового бюджета с тремя источниками).
