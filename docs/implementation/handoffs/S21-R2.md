# S21-R2 handoff

## Outcome

Real Google sign-in, session restore, access refresh, logout and re-login now
pass on a physical Samsung SM-S938B (Android 16) against a configured live
build. Closing the gate required fixing a backend defect: every genuine Google
ID token was rejected with 401 because the certificate-fetch timeout wrapper
refused google-auth's positional transport call. S21 is COMPLETE.

## Root cause

`google.oauth2.id_token.verify_oauth2_token` fetches signing certificates as
`request(certs_url, method="GET")`. S12's wrapper was declared
`def bounded_request(**kwargs)`, so the positional URL raised `TypeError`, which
`verify()` maps to `InvalidGoogleTokenError` and the API answers 401. Every
existing verifier test either injected a fake `verify_token` that discarded the
transport (`del request`) or monkeypatched `_fetch_certs`, so the transport was
never invoked and the suite stayed green. The defect could only appear against
real Google traffic.

The new test drives a fake `verify_token` that calls the transport positionally,
exactly as google-auth does, and asserts the 10-second timeout still reaches the
underlying request. It fails on the pre-fix code with the original `TypeError`.
