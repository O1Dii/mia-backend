## Root cause

`WebSurfaceScreen` hosts the WebView with `AndroidView(factory = { webView })`; the WebView had no layout params, so Compose
gave it `WRAP_CONTENT`. Chromium then runs the WebView in "wrap content" layout and reports a **viewport height of 0** to the
page: on SM-S938B (Android 16, WebView 153) `innerHeight` = 727 but `100vh` = `100dvh` = `100svh` = **0**. The web dialog is capped
with `.mw-dialog { max-height: 90dvh }` → computed `max-height: 0px` → the consent box is just its padding and border:
**49 px**, scrollable inside (exactly «высотой с input»). Playwright could not see it: desktop/mobile Chromium resolves `dvh` normally.
The same collapse also affected every other `vh`/`dvh` rule of the web inside the app (chat height, `min-height: 100dvh`).

## Fix

- Android (root): `createIsolatedWebView` sets `ViewGroup.LayoutParams(MATCH_PARENT, MATCH_PARENT)` on the WebView, so the page
  gets the WebView's real height (after: `100dvh` = 727 = WebView height). No WebView settings changed, no JS bridge.
- Web (defence + the requested size): `.mw-dialog` `max-height: 90%` (percent of the fixed containing block = viewport; immune to
  the vh collapse). Phones (`max-width: 599px`): every dialog `max-height: calc(100% − 32px)`; new `Dialog tall` prop →
  `.mw-dialog--tall` with that height, used by `ConsentDialog` (install and update consent). The consent summary sits in
  `.mw-dialog__body`; a dialog with a body is a flex column where only the body scrolls, so «Отмена»/«Установить» stay on screen.
  Other dialogs (remove, Memory, Inbox, Models, Dashboard, Privacy) only got the viewport-unit-free cap; their content-sized
  look is unchanged. The web has no bottom sheets. "Добавить по URL" is a page, not a dialog (checked).
- No "embedded" flag was needed (OI-UX-001 untouched).

## Decisions

- Fix at the root in Android (the WebView must fill its host) and make dialogs independent of viewport units in web, because any
  future host or browser quirk with `vh` would otherwise bring the bug back.
- «Почти на весь экран»: on phones the consent is full height minus a 16 px gutter regardless of content length (consent is the
  one dialog where reading matters); short confirmations stay content-sized.
- The compose test clock resumes `LaunchedEffect` on an I/O worker after a real network call; the gate test mints the hand-off code
  before composing (test-only; the app resumes on the main thread).
