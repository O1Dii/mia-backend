# M11 handoff

`backend_head_commit` = last code commit; the handoff commit follows it. Branch `session/M11-model-gateway`.

## Outcome

`ModelGateway` (port from M00) is implemented: `mia:default` resolves per user to the primary connection (GPT on a
ChatGPT plan via Sign in with ChatGPT, Responses API), with DeepInfra GLM-5.3-Flash as the ordered fallback; the
other `web_poc` providers are ported as `chat_only`. Connections are stored in PostgreSQL with secrets sealed under a
per-user DEK (master key -> DEK -> AES-256-GCM, master-key rotation, crypto-shred); the CRUD API never returns a key.
The live smoke of the primary model was **not run** (needs an interactive ChatGPT sign-in); a ready command is below.

## Scope completed

- Adapters: `chatgpt-plan` and `openai` (Responses), `deepinfra`/`groq`/`mistral`/`local` (OpenAI-compatible chat
  completions, streaming, `reasoning_content` replay), `anthropic`/`gemini`/`ollama` (`chat_only`, one-shot).
- Provider state (closes OI-W6-013): `ModelToolCall.provider_state` carries Responses reasoning items that have
  `encrypted_content` (`responses_reasoning_items`) and GLM `reasoning_content`; replayed verbatim from the message.
- Sign in with ChatGPT: PKCE, dynamic client registration, persistent `ext_agent_host_id`, multi-threaded loopback
  listener with socket timeouts, ID-token signature check via JWKS (RS256/ES256 allow-list, rate-limited key refetch),
  serialized refresh with rotation (in-process lock + `SELECT ... FOR UPDATE`), revoke on sign-out/delete.
- `subscription_sharing_usage_limit_exceeded` (HTTP 429 or in-stream) pauses the connection (Retry-After or
  `MODEL_USAGE_PAUSE_SECONDS`) and the step fails over to the next `mia:default` candidate if nothing was streamed yet.
- Bounded retry (2x, backoff) for connect errors and 502/503; one token refresh + retry on 401; stream deadline.
- `app/core/crypto.py`: keyring, `seal`/`open_sealed`, wrap/unwrap/rewrap. `KeyVault`: DEK per user, race-safe create,
  `rotate_master_key`, `shred_user`.
- API `/v1/model-connections` (list/create/get/patch/delete, `/{id}/test`, `/{id}/resume`, `/{id}/sign-out`,
  `/chatgpt-plan/sign-in` + status). `/test` is rate-limited (5 s per connection).
- `python -m app.modules.models.smoke` (manual live smoke + scrubbed cassette recording).

## Decisions

- `mia:default` order: primary flag, then `chatgpt-plan`, then creation time; only `tools`-capable connections.
  The first plan sign-in takes over the primary slot (ADR-0014); any PATCH `make_primary` overrides it.
- Fail-over only for `mia:default`, only before the first event, only for usage-limit/reauth/not-configured errors.
  Explicit `<provider>/<model>` never falls over. Mid-stream failures are raised, never continued elsewhere.
- Structured output (assistant-response JSON) is **not** requested on the wire: `ModelInfo.supports_structured_output`
  is False for every adapter, so the run engine must use the ADR-0011 splitter. `max_output_tokens` is not sent in plan
  mode (the plan rejects it).
- `verified=True` only for `chatgpt-plan` with tools; GLM stays unverified until M61.
- Malformed tool-call arguments raise `invalid_request` with `retryable=True` (the port has no better code).
- Local/loopback providers accept only literal `127.0.0.1`/`::1` URLs (SSRF); cloud URLs are fixed.

## Known limitations

- `chat_only` adapters answer in one `TextDelta` (no streaming); Anthropic/Gemini/Ollama are untested live.
- Only function tools; parallel tool calls are parsed but untested live. No per-user rate limit on the API.
- Sign-in state is in process memory (single worker); a multi-worker deployment needs sticky routing for the status poll.
