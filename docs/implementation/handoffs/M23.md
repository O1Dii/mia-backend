## Decisions

- `telegram.handoff` is `write_reversible` with no approval: it only opens Telegram with a draft (L0). With
  `contact_name` and an international number it opens `tg://resolve?phone=…&text=…` and also puts the text on the
  clipboard (marked sensitive) as a safety net; otherwise Telegram's share sheet via `ACTION_SEND` with the package
  set. Never sends.
- Contact search results contain names and a phone count only (M17 minimisation, Review §7.5). `people.resolve`
  (M17) gets `matches[].name`; identifiers are resolved on the phone by `telegram.handoff.contact_name`.
- On Samsung, `getNextAlarmClock` reports a "briefing" pre-alert ~40 s before the alarm, so `verified` is true when
  the next alarm lies within 2 min before the requested time. It is a heuristic and never turns success into failure.
- Revoking a runtime permission kills the app process, so the on-demand prompt tests need `adb shell pm revoke`
  from outside (done by `run_gate.sh`); they `assume` the permission is not granted.
- A contact inserted by the tests uses a private account type (`by.mia.assistant.test`): the phone's default
  account is a Google cloud account, which refuses local contacts, and the test must never sync to Google.

## Known limitations

- Device tool calls arrive only in voice runs (the voice controller follows the stream); chat/job runs need their own follower (M25/M16), as noted in the M22 handoff.
- Tools that need the screen are declared `requires_unlocked`; a locked phone answers `device_locked` (retryable).
- Background launches: `startActivity` from a background process is restricted by Android 10+; tools work from the foreground voice screen and the assistant session, and from instrumentation.
- Leftover on the test phone (cannot be removed headlessly): alarms 03:41 (label "MIA test"/"MIA_test") and 03:17 ("MIA gate"). The user should delete them in the Clock app. The test contact is removed after each test.
