## Outcome

«Напиши Яне в Телеграм, что надо купить молоко» works as a plugin tool `builtin.telegram.send_message {to, text}` (`write_external`, voice): `people.resolve` (M17) gives refs, two «Яны» are clarified before anything else, the router asks for an approval over the exact arguments (M13), then the device tool `telegram.handoff` (L0, M23) opens Telegram with the draft; the tool result says the message is NOT sent. Denial or expiry sends nothing. The Mia bot: one-time deep link `/start <token>`, webhook with a constant-time secret check, `telegram` notification channel for M16 (a job result reaches the bot).

## Decisions

- The plugin is a builtin (module under `app.`, M00): only an in-process server can reach the run's device channel and memory.
- `to` accepts a ref or a name; names are resolved by the plugin (memory first, then the phone's contacts); several matches fail the tool before the phone is touched (the approval was already given for the typed name, see OI-M41-001). SKILL.md makes the model call `people.resolve` first and ask which Яна.
- The tool result never claims "sent": Bot API cannot message other people (Review §7.5); the user presses send.
- Bot link: token = 32 random bytes, hash stored, single use, 15 min, max 5 pending per user; a chat belongs to one user, relinking moves it. Blocked bot / deleted chat unlinks and fails the delivery; 429/5xx/network -> `retry`.
- Redis: DB 41 is out of range (0-15); used own container `mia-m41-redis` (56441) instead of DB 12.
