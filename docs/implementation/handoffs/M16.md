# M16 handoff

Branch `session/M16-jobs`; `backend_head_commit` = last code commit, the handoff commit follows it.

## Outcome

The model can send work to the background and schedule it; results reach the user. A new
process `python -m app.worker` executes jobs from a Postgres queue (`FOR UPDATE SKIP LOCKED`,
renewed lease, retries, attempt history) as `profile=job` runs, fires schedules (RRULE + IANA
TZ, misfire `skip`/`run_once`/`limited_catch_up`) and due M14 timer/alarm/focus deadlines, and
delivers inbox items by push (FCM HTTP v1) with a Telegram extension point. All state is in
Postgres: schedules and in-flight jobs survive worker restarts (proved with the real process
and SIGTERM); 8 concurrent workers never claim one job twice. Core tools `background.*`,
`schedule.*`, `notify` are registered on M13's router; the next interactive run hears «пока вас
не было». OI-WEB-002 is resolved (update in `## M16 inbox`).

## Decisions

- Own `SKIP LOCKED` queue instead of Procrastinate: no new dependency, worker writes are
  conditional on `(lease_owner, attempt)`, run history in `job_attempts`.
- A job is never re-run after a (possible) write: retry/reclaim checks `tool_executions` of the
  run for `write_*` with `succeeded|uncertain|running`; such jobs fail with an inbox notice.
- Occurrence within `JOBS_MISFIRE_GRACE_SECONDS` is on time; `run_once` does not add a late run
  when an on-time one runs; resume/rule change restarts from now (paused gaps are not misfires).
- Timer/alarm firing = worker scan of `PluginState` (jsonpath, paged), no plugin edits; deadlines
  older than 24 h are not fired; `deadline_fires` (kept 7 d) makes firing exactly-once.
- Inbox item + deliveries are written in the job's finishing transaction (nothing lost on crash).
- `kind: reminder` schedules deliver the goal text without a model call (reliable reminders).
- Notifications always create an inbox item; `push`/`telegram` channels are deliveries.
