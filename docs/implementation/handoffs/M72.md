## Outcome

Страница плагина в магазине показывает блок «Где работает»: что идёт в облаке Mia и что может выполняться на телефоне только по
запросу (с возможностями устройства: название, вид, обязательна ли, что увидит модель). Будильник, таймер и Telegram объявляют
телефонные возможности (`alarm.clock`, `telegram.draft`), «Заметки», «Фокус», «Новости», «Интернет» — «телефон не участвует».
Экран согласия (установка и обновление) перечисляет те же возможности. Попутно закрыт OI-LIVE-002: риск инструментов
сервера по URL берётся из MCP-аннотаций (`readOnlyHint` → чтение без подтверждения, `destructiveHint:false` → обратимое
изменение, иначе внешнее действие), показывается у каждого инструмента и правится пользователем на экране добавления.

## Decisions

- **Unannotated tool = `write_external`** (not `write_reversible` as OI-LIVE-002 phrased it): MCP's own default is
  «destructive», and a server that says nothing is not trusted; only `readOnlyHint:true` lowers to read and
  `destructiveHint:false` to reversible. The user can change any tool. Linear (which annotates) reads without prompts.
- **Risk grants are echoed by the client** (`risk_grants` lists the three `tools.<risk>`); the server still derives the
  required set from the resulting manifest and refuses a missing one.
- `whereItRuns` is a separate top-level optional field, not inside `listing`: it is shown on the page and the consent
  screen, and the validator keeps `listing` for the catalog card.
- Telegram's `telegram.draft` is `optional:false` (sending needs the phone); alarm/timer are `optional:true`.
- OI-M41-R1-001 (action buttons from remote plugins): not implemented; see OI-M72-004.
