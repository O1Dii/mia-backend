# S32 handoff

## Outcome

`system.get_current_datetime` is proven, through the composed application, to
behave identically and fail closed in both modalities, with a uniform audit
trail that the model cannot bypass. Nineteen full-stack tests cover text SSE and
realtime, including the real `GeminiLiveAdapter` over a scripted wire transport.
The work exposed two real defects — one in tool-cancellation auditing, one that
made every real Gemini tool call impossible. **The cloud tool smoke on a device
was not run**, so S32 is PARTIAL.

## Scope completed

Text path: tool call → executor → progress and result on the SSE stream →
canonical tool-call/result history; invalid arguments (3 shapes), unknown tool,
oversized arguments, escalated risk, timeout and oversized output all fail closed
with the documented public codes and are audited; a tool result stays untrusted
data and cannot reach `system_instruction` or re-enter the registry; audit is
idempotent per `(user_id, call_id)` and a replay does not re-execute.

Realtime path: a provider-claimed tool completion the executor did not produce is
dropped; the Gemini Live public↔wire ID mapping is exercised through the composed
gateway; cancellation mid-execution is audited and leaks no result.

Cross-modality: one registry and one executor govern both paths, with identical
denial payloads and uniform audit rows.

## Defect 1 — cancelled tool calls were never recorded

`RealtimeConnection` cancels a tool task on `response.cancel` and again in its
teardown `finally`. Every `Task.cancel()` delivers a fresh `CancelledError`, and
`anyio.CancelScope(shield=True)` does not shield against a raw `Task.cancel()`,
so the second cancel landed inside the shielded finalizing write and rolled the
audit transaction back. The row stayed `running` forever, and because `_claim`
maps an existing `RUNNING` row to `tool_execution_failed`, a later replay of that
`call_id` got the wrong terminal answer. S17's stated guarantee that
"cancellation is recorded" was false on the barge-in-then-hang-up path.

`_finish_cancelled()` now runs the finalizing write as its own task and waits it
out across repeated cancellations. Regression tests cover 1, 2 and 3 cancels;
`tests/tools/test_executor.py` passes unchanged because it cancels once.

## Defect 2 — every real Gemini tool call failed

Found by the device gate, repaired in [S17-R1](S17-R1.md): the registry's raw
JSON Schema was rejected by both Gemini surfaces, so no real tool call could ever
be issued. Verified fixed against the live API for text and Live.

  produce the condition (timeout, >2 KiB output), the tool *handler* — while
  asserting the substituted registry keeps the production definition, risk,
  2 s timeout and 2048-byte output cap.
- The executor fix tolerates the double cancel rather than changing the gateway,
  which is another session's file; the gateway behaviour is recorded as
  OI-W6-010 instead.
