## Outcome

`DELETE /v1/account` deletes the account from the web («Ещё» → «Удалить аккаунт», ввод «УДАЛИТЬ») and from Android
(«Настройки» → «Аккаунт» → «Удалить аккаунт», тот же ввод). An incognito switch in the web chat, the Android chat and the
Android voice screen sends `incognito: true` runs and shows a sign. Both strict xfails of
`tests/e2e_mvp/test_s07_memory.py` are removed and pass.

## Deletion (`app/modules/users/deletion.py`, `app/api/v1/account.py`)

Bearer or cookie (cookie: same-origin, as every cookie mutation), `Idempotency-Key` required. Order:
1. unfinished runs of the user are cancelled and awaited ≤ 5 s;
2. `ConnectionService.revoke_all_for_user` (new, additive in `app/modules/connections/oauth/service.py`): every plugin
   connection is deleted and its tokens revoked at the provider (RFC 7009, best effort) — before the key is gone (OI-M15-006);
3. `MemoryService.shred_account`: memory rows deleted, DEK crypto-shredded;
4. one transaction: lock `users` row, insert the journal row, delete the row. Everything cascades (checked on the live
   schema: every FK to `users` is CASCADE, except `plugin_releases.published_by` SET NULL): Android refresh families and
   devices, web/WebView sessions, Mia sign-in grants/tokens/codes («Войти через Mia»), push tokens, Telegram link and
   link tokens, chats, runs, jobs, inbox, workspace + installations, model connections, idempotency keys.
Steps 1–3 are repeatable; a failure answers 503 `account_deletion_incomplete` (retryable) and the account still works.
Afterwards the old bearer/cookie answer 401 (the browser cookie is also cleared), a new Google sign-in creates a new,
empty account. Journal: table `account_deletions` (`user_id` without FK, `deleted_at`, `requested_via`
bearer|cookie, `provider_connections`, `memory_shredded`) + log line `account_deleted` — no content, no e-mail/sub.

## Decisions taken without the user

- Confirmation = typing «УДАЛИТЬ» (case-insensitive) on web and Android; one idempotency key per opened dialog.
- Audit = separate table without FK (memory access log cascades away with the user); keeps the random user id only.
- 401 on a retry after success is treated as success by both clients (OI-M17-R1-001).
- Incognito is a mode of the chat screen: messages stay on screen only; opening another chat (or a new one) ends it;
  web keeps it when coming back to the same address; Android chat and voice switches are independent.
- Incognito runs are single-turn (OI-M17-R1-004).

## Known limitations

- Model-provider credentials (ChatGPT sign-in) are destroyed locally, not revoked at OpenAI (OI-M17-R1-002).
- Backups keep plain data (chats, runs) until they expire; memory/secrets in them are unreadable (OI-M17-R1-003).
- The Telegram bot gets no goodbye message; the chat is simply no longer linked.
- Android voice incognito resets when the voice screen is reopened; the chat switch does not carry over to voice.

## Proposed user check (UC-M17R1-1, после деплоя)

1. Веб, тестовый аккаунт: в чате нажмите значок маски «Инкогнито» → появилась синяя полоса «Инкогнито…», старые сообщения
   скрылись. Напишите «Запомни, что я люблю чай» → в «Памяти» ничего нового, в истории чатов этого разговора нет.
   Нажмите значок ещё раз → чат вернулся.
2. Телефон: то же в чате (значок в шапке) и на экране голоса (переключатель «Инкогнито» под кнопкой).
3. Тестовый аккаунт с подключённым плагином: «Ещё» → «Удалить аккаунт» → введите «удалить» → «Удалить навсегда».
   Открылся экран входа с «Аккаунт удалён». На телефоне с этим аккаунтом любое действие просит войти заново.
4. Войдите снова тем же Google → пустой аккаунт: нет памяти, чатов, плагинов. (На Android можно начать с п. 3 из
   «Настройки» → «Удалить аккаунт».)
