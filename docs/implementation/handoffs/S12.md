## Decisions

Only token hashes persist. Idempotency-Key never replays token responses or
bypasses nonce/reuse protections. Repeating nonce creation issues a fresh nonce.
Clients serialize refresh and reauthenticate after ambiguous refresh outcomes.
Unexpired access survives normal rotation, but fails after family revocation.
Official sources: [Google verification](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token)
and [OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect).
