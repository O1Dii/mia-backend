## Outcome

«Интернет» (`search`/`news`/`read`) is available to every user without installing it. In chat the model answers factual and
news questions itself, with source links, and uses `background.start` only for long, deferred or explicitly requested work
with the goal in the user's words. The model prompt carries the user's local date, weekday, time and time zone.
`tool.call.started` now carries the redacted arguments and `tool.call.completed` the reason of a failure; `builtin.news.refresh`
and the search tools name the query and the reason when there is no result.

- User date and time zone in the system instruction (was UTC ISO string).
- Tool-call journal: `arguments` (redacted) and `error_detail` (reason) in `tool.call.*`; contract and fixture updated.
- Search/news/read/`news.refresh` errors and empty results now include the query and the reason.
- Tests: DoD scenario with the real router, redaction, prompts, always-on reader.

## Contracts produced or changed (additive, `contracts/mvp/v1/run-events.schema.json`)

For M75 (web) and M76 (Android):

- `tool.call.started.payload.arguments` — object, optional. The model's arguments, **redacted**: secret-looking keys
  (`password`, `token`, `api_key`, `authorization`, …) → `"[скрыто]"`; e-mails → `"[email]"`; phone-like numbers → `"[телефон]"`;
  opaque tokens (≥ 32 chars with letters and digits) → `"[скрыто]"`; strings clipped to 300 chars, ≤ 20 items, depth 4, whole object ≤ 2000 bytes
  (otherwise reduced and `"_truncated": true`). For `executor = "device"` every string value is `"[скрыто]"` (shape only).
- `tool.call.completed.payload.error_detail` — string 1..300, optional. Present only when status is not `succeeded` and the tool gave a reason
  (e.g. `Поиск новостей по запросу «курс доллара» не удался: Источник недоступен…`, `По запросу «ИИ» за последние 48 часов публикаций не найдено…`).
  The stable machine code stays in `error.code` (`tool_execution_failed`, `tool_unavailable`, …); `error.message` is the fixed English text.
- Journal row to render: `tool` + `arguments` (from `started`, joined by `tool_call_id`) + `status` + `error.code` + `error_detail`.
  Failed rows should show `error_detail` open; successful ones may keep arguments collapsed.
- No schema change in `common.schema.json`/`error-codes.json`; no new error codes.

## Decisions

- **Always-on via a reader decorator, not an installation row.** A row per user would need a migration/backfill and could go stale (digest);
  the virtual record is computed from the package in the running image, so a redeploy never blocks search. Rejected: auto-installing at sign-up (data migration, can be uninstalled).
- **Journal data come from the engine** with what the router already returns (`outcome.content` for the reason), so `router.py` stays untouched.
  Failed plugin calls return the tool's message as framed content; the frame is stripped and the text redacted.
- **Tool descriptions of `builtin.internet` were not changed**, only result texts and SKILL.md: a description change alters the tools digest and would block existing installations until re-consent.
- **Date in the user's zone**, with weekday and an explicit rule that «сегодня/завтра» follow it; unknown zone falls back to UTC.
- **Device arguments are shape-only** (ADR-0016 minimisation); server tool arguments keep their values after scrubbing, because they are the user's own query and are needed to explain a failure.
