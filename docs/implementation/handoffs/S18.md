# S18 handoff

## Outcome

The backend is deployable for internal beta without feature-scope changes: logs are
an allow-list of server-authored events that never carry messages, arguments,
exception text, paths, query strings or content; every HTTP and WebSocket request
carries a correlation ID that also reaches module loggers and Prometheus metrics;
text turns and Live sessions are admitted through fail-closed per-user Redis day
budgets, an active-session cap, a WebSocket duration cap and provider circuit
breakers; readiness additionally refuses traffic until PostgreSQL is at the
Alembic head packaged in the running image. The image runs unprivileged from the
locked virtualenv, migrations run as a separate release step with the same image,
and staging Compose, backup/restore drill and dependency/static security scans are
scripted and verified. Full backend gate, container smoke and migrations on empty,
previous-head and populated databases pass; no advisory remains in the lockfile.

## Scope completed

- Structured JSON logging with redaction, including uvicorn/alembic loggers, plus
  access logs disabled and exception classes logged without messages or tracebacks.
- Correlation middleware (HTTP + WebSocket) with request-ID validation, echo,
  contextvar propagation, duration and route-template logging.
- Metrics registry and opt-in `/metrics` (requests, durations, WebSocket
  connections, admission rejections, circuit state, readiness results).
- Daily per-user text/Live budgets in Redis, active Live session cap, Live session
  duration cap with a contract error, kill switches, text and Live circuit breakers.
- Readiness: bounded 2 s deadline, PostgreSQL + Redis + schema-head gate, typed
  failure reason logged and counted.
- Deployment: unprivileged image, HEALTHCHECK, proxy headers, migration release
  step in local and staging Compose, read-only/cap-dropped staging service.
- Ops: `ops/README.md` runbook, `ops/backup_restore_drill.sh`,
  `ops/security_scan.sh`, CI security job.
- Dependency hardening: advisory-fixing upgrades and the direct `websockets` pin.

## Decisions

- Log free-form client `X-Request-ID` values as a SHA-256 prefix and only
  UUID/hex-shaped IDs verbatim: correlation stays possible without ever echoing a
  client-chosen string into logs.
- Charge Live sessions after the store admits them and release the session when the
  budget denies it, so an active-session rejection never consumes daily quota.
- Bound the Live session by a watchdog that emits `rate_limit_exceeded` and closes
  with 1008, instead of cancelling the connection task, so clients see a reason.
- Gate readiness on the packaged Alembic head so a skipped release step or a
  rolled-back image never receives traffic.
- Keep `google-genai==1.10.0` and declare `websockets==15.0.1` directly
  (OI-S16-001); no SDK migration was attempted in a hardening session.

## Known limitations

- Realtime claims, the active-session cap, circuit breakers and metrics are
  process-local: run exactly one backend instance, and expect metrics to reset on
  restart (OI-S18-002). Abrupt death still leaves no durable claim to clean up.
- `/metrics` has no authentication; it must stay off the public proxy route.
- The in-memory realtime store keeps finished session records until restart; the
  daily session budget bounds that growth.
- Rate limits use the peer address, so `FORWARDED_ALLOW_IPS` must name the proxy.
- No cloud provider smoke ran here; S31/S32 still own real Gemini verification.
