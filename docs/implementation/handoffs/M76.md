## Outcome

The Android app has chats (ADR-0017). The title bar shows the current chat's title with buttons «Чаты», «Новый чат», voice and settings;
the chat list (`chats` route) opens, creates, pins, renames and deletes chats; the side key starts a new dialog and offers
«Продолжить: <название>» on the voice screen for five minutes after the last answer; a new dialog is created on the server only with
its first question (voice or text). «Сейчас» (timers, alarms, focus, background tasks) is a strip under the title bar with a live
countdown and «Отменить», and running timers appear as ongoing notifications with a system countdown. Markdown tables render as
scrollable tables, tool steps show their arguments and the failure reason, and job result cards in the feed carry a label.

## Scope completed

- Chat list and new chat: `ChatListPresenter` + `ChatListScreen` (route `chats`), open / new / pin / rename (inline) / delete (inline confirm);
  current chat marked; pinned first (server order); Telegram chat can be pinned/deleted, not renamed.
- Switching chats: `ChatPresenter` follows the shared `ChatSelection`; feed per `conversation_id`; the default chat is resolved to its id after the
  first load (so voice goes to the same chat); a deleted chat falls back to the default chat.
- Side key = new dialog: `AssistantEntry.launches` and a cold assistant launch call `ChatSelection.beginAssistantDialog()`; «Продолжить прошлый»
  from `GET /v1/chats/continue?within_seconds=300`; repeated press with voice already open keeps the session (KEEP, unchanged).
- Voice into the chosen chat: `CascadeVoiceController(conversationId, onTurnFinished)`; the chat is created (lazily, same `Idempotency-Key` on retry) before the first run.
- «Сейчас»: `NowPresenter` (refresh on show, after a run, on a due countdown, every 30 s while anything is active), `NowStrip`,
  cancel (tile tool / job), `AndroidNowNotifier` (ongoing, silent, chronometer count-down, auto-dismiss at the deadline).
- OI-LIVE-001 (Android): pipe tables. OI-LIVE-003 / OI-M73-002 (Android): `arguments`, `error_detail` per step; `FeedItem.card` label.

## Decisions

- New dialog is lazy (OI-M76-001); the offer is fetched when the key is pressed, not when the screen is shown.
- `ChatSelection` (core/network) is the only shared state: target `Latest | Fresh | Existing(id)`. The chat screen reads it on `onShown`; voice reads it per question.
- Switching never cancels a running answer (OI-M76-003).
- Rename/delete are inline in the list row, not dialogs (Robolectric dialog windows stalled idling; also fewer layers on a phone).
- Voice pill in the title bar is icon-only to leave room for «Чаты» / «+» on 360 dp phones (content description unchanged).
- Notification timer uses the platform `Notification.Builder` chronometer (no foreground service, no periodic updates).

## Known limitations

- «Сейчас» in the shade is driven from the app process; a timer set elsewhere shows after the app opens (OI-M76-004). No «Отменить» button in the shade.
- Approval cards of a run left behind in another chat are not restored (OI-M76-003).
- Tool steps are kept for the session, not in the server feed (OI-M76-007).
- The mock flavor's feed ignores the chat id (one history); its chats/timer are in-memory stand-ins.
