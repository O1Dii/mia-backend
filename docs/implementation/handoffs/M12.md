# M12 handoff

Branch `session/M12-run-engine`; `backend_head_commit` = last code commit, the handoff commit follows it.

## Outcome

Every request is a persisted run with an append-only, gap-free event log streamed over
SSE `/v1/runs/{id}/events` with resume by cursor (SSE id / `Last-Event-ID` / `?cursor=`).
The engine runs context → `ModelGateway` → `ToolRouter` (+ `ApprovalService`) → final
`{speech, display, followups}` under per-profile budgets from config, supports cancel
(`cancel_requested` → `run.cancelled`), emits `speech.ack` for slow voice answers and
writes voice/chat into one primary user feed with an episodic summary. Every emitted event
is validated against `run-events.schema.json` in tests on both the in-memory and the
Postgres store; 20 parallel runs stream without mixing.

## Scope completed

- `app/modules/runs/`: `domain` (statuses, `RunCursor`, `run_effects` state machine),
  `models`/`store` (`InMemoryRunStore`, `SqlRunStore`: row-locked append, one terminal
  event, idempotent create via `idempotency_keys`), `notifier`, `profiles`, `response`
  (parser), `prompts`, `engine` (`RunEngine`/`RunExecution`), `service` (`RunService`),
  `summarizer`, `defaults` (placeholders), `errors`, `composition` (`install_runs`).
- `app/api/v1/runs.py`: `POST /v1/runs`, `GET /v1/runs/{id}`, `GET …/events` (SSE,
  `: keepalive` comments), `POST …/cancel`; public error envelope, no input echo.
- `app/modules/conversations/feed.py` (`FeedService`, `ExtractiveFeedSummarizer`); models:
  `Conversation.is_primary_feed`, `summary_until_sequence`, `TurnSource.RUN_*`.
- Loop rules: last allowed step gets no tools (voice: 3 steps / 2 tool calls); calls over
  the tool budget get `{"status":"skipped","error":"tool_budget_exceeded"}`; voice sees
  only `voice` tools; unknown tool / reused call id handled without execution; approval
  wait is cancellable and excluded from the time budget; tool calls in flight finish
  before cancel takes effect; time budget → `run.cancelled{budget_exceeded}`.
- Speech/display: structured JSON (fenced/wrapped tolerated, normalized to the schema)
  or heuristic «first sentence = speech», full text → `display.text`; speech is plain and
  clipped to the profile limit (voice 250, hard 300).
- Recovery: heartbeat every 10 s; a non-terminal run with no local task and a stale
  heartbeat (60 s) is ended with `run.failed{run_interrupted}` (or `run.cancelled` when
  cancel was requested) on access; shutdown-cancelled tasks write `run_interrupted`.

## Decisions

- Store is the source of truth; the notifier only wakes local readers, readers re-poll on
  keepalive (15 s), so other processes' events are seen too.
- `message.delta` only for chat/app in plain-text mode (JSON drafts are not displayable).
- Voice runs reject `conversation_id` (`voice_feed_only`); incognito runs neither write
  the feed nor read memory and do not store `input_text`.
- `job`/`app` runs are created internally (`RunService.start(NewRun(profile=...))`), not
  via public `POST /v1/runs`.
- Public error messages are fixed strings; `ModelGatewayError.message` is never exposed.

## Known limitations

- Live-run map, cancel signal and notifier are per process (single instance, OI-S18-002);
  cross-instance cancel is honoured at the next step boundary.
- No retention/TTL; `run_events` grow per run (deltas coalesced at 160 chars/150 ms).
- Summary is produced by the user's own model (`ModelFeedSummarizer`, profile `job`) with
  an extractive fallback; quality untested on the primary model.
