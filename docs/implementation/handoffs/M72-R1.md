# M72-R1 handoff

Branch `session/M72-R1-url-risks` (worktree `mia-helper-wt/M72-R1`), base `6ac34c0`. 1 code commit, 1 docs/web commit and this handoff. Nothing
merged or pushed. No migration (the marker lives in the stored `mia.json`).

## Root cause

Linear was added by URL before M72: its stored overlay holds 76 tools, all `write_external`. M72 derives a risk from MCP
annotations only when a server is *added*; at call time the router uses the stored risk. M72 also treated every stored risk as
«the user's saved choice» on re-pick. So the live Linear kept asking for confirmation, and nothing re-derived it. Annotations
are not part of the tools digest, so a listing with an unchanged digest carried them without any block, and nobody read them.

## Outcome

- New marker `tools.<name>.riskSource` in the stored manifest of a server by URL: `user` (chosen on the add screen, never
  re-derived), `annotation` / `default` (derived by Mia). Absent = stored before this repair.
- `McpToolRouter._plugin_entries` (after the digest check) calls `rederive_risks`: an unmarked tool takes the risk derived from
  the annotations of the tools just listed (up or down); the result is used for **this** call (so the approval decision in
  `call()` sees it) and frozen in the installation row by `SqlRiskStore` (only while the stored manifest is unchanged, only
  `source = custom`, `state_version` and grants untouched). The next listing finds nothing to do.
- A marked derived tool only moves **up** (a server that later calls a tool destructive makes it ask; the reverse waits for a
  new consent). `user` tools and tools the server no longer lists are never touched.
- Consent: `custom_manifest` writes `riskSource`; `_saved_risks` returns only `user` risks; `consent_custom` carries saved user
  risks of the chosen tools over unless the request changes them (before, re-saving without edits silently reverted them).
- Web (`StoreAddUrl.tsx`): chip «изменено вами» for the user's risk (saved or just edited); «по пометке сервера» stays for derived.

## What happens to the live Linear installation (`custom.ufb39103c7d2edac`) after deploy

No re-add, no migration, no re-consent: the digest is unchanged. At the first tool listing of any chat run (for example
«покажи мои проекты») the router re-derives the 76 risks from Linear's current annotations, logs `plugin_risks_rederived`
(`plugin_id`, `installation_id`, `tool_count=76`), and stores them with `riskSource`. If Linear sends `readOnlyHint`, its
`list_*`/`get_*` tools run without confirmation; creates/updates without hints keep asking; `delete_*` keep asking. If the
tool budget trims Linear (M15-R1), only the offered tools are re-derived in memory, the whole stored overlay is frozen.
