# Мия Web POC

Web-прототип новой платформы: магазин плагинов, собственные модели/API-ключи,
дашборд, модельные инструменты, SDK приложений и импорт manifest v2/AI-рецептов. План: [WEB_PLATFORM_PLAN](../docs/WEB_PLATFORM_PLAN.md).
Контракт плагинов: [PLUGIN_DEVELOPMENT](../docs/PLUGIN_DEVELOPMENT.md).

## Запуск

Нужны Python 3.12+, `uv`, Node.js 22.18+ и npm. PostgreSQL, Redis и `.env` не нужны.

В первом терминале из корня репозитория:

```sh
uv sync --frozen --all-groups
uv run --frozen uvicorn app.web_poc.main:app --host 127.0.0.1 --port 8001 --no-access-log
```

Во втором терминале:

```sh
cd web
npm ci
npm run dev
```

Открыть [http://127.0.0.1:5173](http://127.0.0.1:5173). Web API работает на 8001,
существующий Android backend на 8000 можно запускать независимо. Vite проксирует
`/api/web`. Для просмотра собранного приложения: `npm run build && npm run preview`
при запущенном web API; адрес preview — `http://127.0.0.1:4173`.

Если локальная npm-конфигурация направляет публичные пакеты в недоступный registry,
используйте отдельные пустые config-файлы, не просматривая credential configuration:

```sh
touch /tmp/mia-empty-npmrc
NPM_CONFIG_USERCONFIG=/dev/null NPM_CONFIG_GLOBALCONFIG=/tmp/mia-empty-npmrc npm ci --registry=https://registry.npmjs.org
```

## Google-вход и серверная версия

По умолчанию localhost остаётся анонимным для разработки: экран Google-входа
здесь не появляется. Серверная конфигурация требует аккаунт и показывает
«Продолжить с Google» перед загрузкой личного пространства. На общем сервере
используется уже настроенный Google OAuth, без копирования client secret.
Опубликовано: [https://mindmapgen.xyz/mia/](https://mindmapgen.xyz/mia/).
На главном экране общего сервиса появилась плитка «Мия».
Инструкции и состояние: [deploy/README](../deploy/README.md).
Регрессия возврата после Google OAuth: `node web/scripts/verify-hosted-auth-return.mjs`
из корня, против публичного сервера, без входа в реальный аккаунт.
Скриншот готовой сборки: [Google-вход](../docs/previews/mia-google-login.png).

## Попробовать

1. В магазине добавить таймер, заметки или часы. Разрешения показываются перед
   установкой. Нажать изображение или название карточки: откроется страница
   с описанием, примерами команд, двумя скриншотами, правами и отзывами.
   В аккаунте можно оставить/изменить/удалить свой отзыв об установленном плагине.
2. В «Модели и ключи» выбрать провайдера, ввести свой ключ и точный ID модели.
   Можно иметь несколько подключений одного провайдера. Сохранение не делает
   платного запроса; «Тест API» проверяет реальный ответ небольшой генерацией.
3. Выбранное подключение используется в диалоге, сводке и пользовательских рецептах.
   Нет автоматического переключения провайдера при ошибке.
   Установите «Таймер», напишите «Поставь таймер на 5 минут» и откройте «Дашборд».
   Для DeepInfra пример ID — `zai-org/GLM-5.3-Flash`; нужен доступ к этой модели.
   Если модель не поддерживает native tools, добавьте подключение в JSON-режиме.
4. В «Для авторов» изменить пример JSON, добавить рецепт, открыть его из библиотеки.
   Скачать JSON и передать другому пользователю для импорта.
5. В «Дашборд» → «Настроить» менять размеры и порядок плиток. «Коротко о главном»
   автоматически устанавливает «Интернет», собирает RSS по темам, суммирует выбранной
   моделью. Можно явно включить автообновление, расходующее API выбранного провайдера.
6. В диалоге нажать микрофон, надиктовать и проверить текст, затем отправить.
   Ответ можно прослушать кнопкой динамика или включить автоозвучку.
   Распознавание доступно не во всех браузерах; при отказе в разрешении работает
   обычное поле ввода. Браузер может обрабатывать аудио через свой сервис.
7. «Приложения и доступ» → скачать таймер с SDK или открыть отдельную вкладку.
   Привязать по коду и управлять тем же отсчётом из самостоятельного приложения.

Ollama: запустить сервис на `http://127.0.0.1:11434`, загрузить модель и указать
её точное имя (например, `llama3.2`). LM Studio: включить local server, загрузить
модель и использовать её ID из интерфейса LM Studio; адрес обычно
`http://127.0.0.1:1234/v1`. Допускаются другие loopback-порты от 1024. Сервер
модели работает на компьютере web API. Удалённые endpoints и произвольные облачные
адреса в этом локальном POC не поддерживаются.

## Данные

API-ключи находятся только в памяти FastAPI. Перезапуск или истечение 8-часового
runtime удаляет подключения. Ключи не сохраняются в browser storage или SQLite;
после restart нужно добавить их заново. В hosted режиме постоянный Google-аккаунт
связан с изолированными установками, состоянием плагинов, дашбордом и отзывами:
они сохраняются в SQLite и переживают restart. Cookie аккаунта — Secure/HttpOnly,
30 дней с возможностью отзыва. SDK grants остаются в памяти до часа; приложение
нужно привязать заново после restart. В анонимном localhost режиме установки и
состояние остаются временными, до 8 часов/restart; reload страницы их сохраняет.
Старая локальная библиотека/рецепты импортируются только в анонимном режиме,
не переносятся в новый Google-аккаунт. Диалог очищается при уходе с экрана.

В hosted режиме Ollama/LM Studio на loopback отключены: сервер не может обратиться
к модели на компьютере пользователя. Для этого потребуется локальный companion.
Локальная разработка по-прежнему поддерживает оба варианта.

Таймеры/будильник продолжают отсчёт вне диалога, но вкладка должна оставаться
открытой для своевременного сигнала. Сон системы и throttling могут задержать
напоминание; после перезагрузки браузер может блокировать звук до нового жеста.
Пока нет push, background service, повторяющихся/множественных будильников или
durable фоновых заданий. Автообновление сводки работает при запущенном API
в пределах сессии. Удаление плагина отменяет его отсчёт и сохраняет заметки.

Есть localhost и hosted POC-конфигурации. Для полного продукта ещё нужны vault,
production grants/versioning, connector и durable jobs из WEB-P2. Оплаты нет.

## Проверка

Из корня:

```sh
uv run --frozen ruff check app/web_poc tests/web_poc
uv run --frozen ruff format --check app/web_poc tests/web_poc
uv run --frozen mypy app/web_poc tests/web_poc
uv run --frozen pytest tests/web_poc tests/auth/test_google_verifier.py
```

Из `web`:

```sh
npm run build
npm run format:check
npx playwright install chromium
npm test
```

Playwright сам запускает localhost web API и Vite, либо использует уже запущенные
серверы. Browser journeys используют изолированное browser storage. Ключевые browser journeys идут через реальный API и временный
локальный HTTP-сервер модели; платных cloud-запросов нет. Python tests проверяют
форматы восьми адаптеров через `httpx.MockTransport`, session isolation,
безопасные ошибки, размеры, локальные endpoints и secret boundaries. Реальный
cloud smoke пока не выполнялся; его можно сделать кнопкой «Тест API» со своим ключом.

## Основные файлы

- `src/App.tsx` — магазин, библиотека, маршруты, установка, студия автора.
- `src/plugins/catalog.ts` — карточки и строго ограниченный manifest рецепта.
- `src/plugins/Tools.tsx`, `scheduler.ts` — web-плагины и отсчёт.
- `src/components/Models.tsx`, `Chat.tsx` — подключения и диалог.
- `src/components/PluginPage.tsx` — описание, скриншоты, отзывы.
- `src/lib/auth.tsx`, `voice.ts` — Google-вход и браузерные речевые API.
- `src/lib/api.ts`, `workspace.tsx` — API и синхронизация общего состояния.
- `src/components/Dashboard.tsx`, `LinkedApps.tsx` — виджеты и привязка приложений.
- `../packages/mia-sdk/` — работающий JS SDK и отдельное HTML-приложение.
- `../app/web_poc/` — отдельный локальный API и provider adapters.

Иллюстрации карточек и hero созданы CSS/SVG, поэтому не требуют скачивания
картинок или AI generation. Google Font имеет системный fallback; без внешней
сети приложение и локальные плагины продолжают работать.
